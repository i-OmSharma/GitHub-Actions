Workflow: The entire CI/CD process (the .yml file).
Job: A specific stage (e.g., "Run Tests", "Build Docker Image").
Step: Individual commands inside a job (e.g., npm install, go test).

every time you push code, this entire process runs in a fresh, clean environment (the Runner).

An event triggers starts a workflow, and the workflow then runs its defines jobs or tasks.
Within that workflow we have 1 or more jobs each of those job have one or more steps within them and they can be ordered in secipic manner and 
runner is the actual server env that is going to execute the job

Between the steps you are in same compute env.
Within the job you are different compute env.

---------------------------------------------------------------------------------------------------------------------------------------

needs -> outputs & results from dependent jobs

steps -> prior steps' outputs, outcome/conclusion

secrets -> secret values incl. GITHUB_TOKEN (GitHub masks but be cautious)

vars -> repo/org/environment-level config variables (great for cross-workflow settings)
-------------------------------------------------------------------------------------------------------------------------------

github -> run & event metadata (repo, ref, sha, event_name, etc.)

env -> variables set at workflow/job/step scope (override rules: step > job > workflow)

matrix -> current matrix values (e.g., os, node)

strategy -> matrix strategy info (job-index, job-total, fail-fast, max-parallel)

job -> current job status; container/service info

runner -> runner OS/arch/temp/tool_cache

inputs -> parameters to reusable/workflow_dispatch workflows

- Data will beusploaded to remote object storage 
- Capped y 10gb by default 


Restore Attempt: First, the job attempts to restore the cache using a defined cache key. If a match is found (a cache hit), the workflow can skip the installation steps entirely.
Conditional Check: If the restore fails (a cache miss), the workflow proceeds to the next steps, which are often wrapped in an if condition to only execute when the cache is missing.
Populate and Save: During this "miss" phase, the workflow performs the necessary work—such as installing dependencies or building files—and includes a step to save those newly created files into the cache so they are available for future runs.

Third party permission Auth

there are two primary mechanism to auth to external systems:

1. Static Credentials (like API key)
    - Long lived via credential lived via GHA repo/env secret
    - Less secure
    - Compatable with everything

2.OIDC Token -> Open ID connect
    - Short-lived credential retrived in runtime 
    - More secure 
    - Require service to support OIDC
